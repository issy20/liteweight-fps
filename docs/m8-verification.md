# M8: 性能計測・実機検証

この文書は、仕様 §10.4（性能計測）と §11.2（手動テスト）を実機で実施するための手順を定義する。取得した結果は [docs/m8-results.md](m8-results.md) に記録する。未実施のOS・項目は「未検証」と明記し、CIのビルド・自動テスト結果で代替しない。

## 0. 共通

- ビルド: `cargo build --locked --release --bin liteweight-fps`（Release）。
- 記録する環境:
  - OS名・バージョン、CPU、GPU、GPUドライバ、RAM、電源モード
  - ディスプレイ解像度・リフレッシュレート・スケーリング
  - Rustバージョン（`rustc -V`）、対象リビジョン（タグ／コミット）
- 各条件は最低3回、A→B／B→A のように順序を交互に実施し、バックグラウンド負荷と熱状態を一定に保つ。
- 計測中はウィンドウを切り替えない・最小化しない。
- ログ・スクリーンショット・計測ファイルを残す。

## 1. 性能計測

### 1.1 計測ツール（OS別）

- Windows: PresentMon（`PresentMon.exe --process_name liteweight-fps.exe --output_file capture.csv`）、CapFrameX。GPU使用率はタスクマネージャー。
- Linux: MangoHud（`MANGOHUD=1 ./liteweight-fps`）、VSync無効化に `vblank_mode=0`。GPU使用率は `intel_gpu_top`／`nvtop`。
- macOS: Metal HUD（`MTL_HUD_ENABLED=1 ./liteweight-fps`）、Instruments（Time Profiler / Metal System Trace）、Activity Monitor。
- メモリ: 各OSの標準ツール。起動時間: プロセス開始からタイトル表示まで。

### 1.2 条件

- BOT数: 5 / 10 / 20
- 内部解像度: 720p / 1080p（設定の解像度・内部解像度倍率で調整）
- 状態: 静止 / 移動（ダッシュ入力）/ 射撃（連射）
- VSync: on / off

### 1.3 記録項目

平均FPS、1% Low、p99フレーム時間、CPU/GPUフレーム時間（取得可能な場合）、プロセスメモリ、起動時間、Draw Call数（取得可能な場合）。

### 1.4 合格基準

- 基準機で 720p / 5 BOT / 60 FPS（§2）。メモリ150MB以下はストレッチ目標。
- 未達の場合はボトルネックを特定し、目標または実装を見直す（§2, §14）。
- 「基準機」は一般的な内蔵GPU搭載ノートPCとし、具体的な機種は実測後に確定する（§14）。

## 2. 実機テスト（§11.2）

対象: Windows 10/11 x64、Linux x64（X11 と Wayland を別々に）、macOS（Apple Silicon / Intel）。

- A. 起動・入力: 起動、マウス捕捉・解除・再捕捉、フォーカス切替、最小化→復帰、遮蔽（occluded）、終了（タイトルQuit／ポーズExit／ウィンドウを閉じる）。
- B. 表示: リサイズ、解像度設定（960×540〜1920×1080）、フルスクリーン切替、内部解像度倍率（50/67/75/100%）、VSync、FPS上限。16:9・16:10・横長で黒帯・歪みなし。
- C. 音声: 3武器の射撃音、リロード、足音（歩行／ダッシュで間隔差）、着地音、命中／ヘッドショット／キル音、音量即時反映。音声デバイス無しでも無音で続行。
- D. ゲームプレイ手動: 高速フリック、ADS連打、射撃とリロードの競合、ダッシュ・ジャンプ中の射撃、武器切替（下ろす／構える・切替中の射撃抑止）、スナイパーADS（移行と暗転、FOVのみ変化でピッチ不変）、壁際（めり込み・引っ掛かりなし、表面模様で識別）。
- E. 安定性: 5分以上の連続プレイ（Free Training と Tracking Aim の両方）でクラッシュ・入力喪失・顕著なフレームスパイクなし。

## 3. 記録と完了判定

- 結果は [docs/m8-results.md](m8-results.md) に、OS×項目の Pass / Fail / 未検証 を表形式で記録する。
- 実機が無いOS・未実施項目は「未検証」と明記する。CI成功を実機確認と扱わない。
- 性能値から最低GPU・製品上限を決定し（§14）、目標達成または見直しを記録する。
